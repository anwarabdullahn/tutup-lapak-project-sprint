# Tutup Lapak Helm Chart

## Prerequisites
- Kubernetes cluster (kubeconfig file: gojo.kubeconfig)
- Helm 3.x
- gcloud CLI (authenticated with service account JSON)
- Docker / BuildKit

## Authenticate & Configure
```bash
# 1. Use provided kubeconfig
export KUBECONFIG=$(pwd)/gojo.kubeconfig

# 2. GCP service account auth (file renamed/placed locally)
export GOOGLE_APPLICATION_CREDENTIALS=$(pwd)/ps_sa.json
gcloud auth activate-service-account --key-file "$GOOGLE_APPLICATION_CREDENTIALS"

# 3. Configure Artifact Registry auth
# (repo scope may vary)
gcloud auth configure-docker us-west1-docker.pkg.dev
```

## Build & Push Images
Tag commit SHA:
```bash
COMMIT_TAG=$(git rev-parse --short HEAD)
REG=us-west1-docker.pkg.dev/projectsprint-000001/ps-docker-repo/gojo

# Example build & push loop
declare -a SVCS=(auth-service product-service backend-infra profile-service purchase-service)
for s in "${SVCS[@]}"; do 
  (cd $s && docker build -t $REG/$s:$COMMIT_TAG . && docker push $REG/$s:$COMMIT_TAG)
done
```

## Install Chart
Namespace changed to `gojo-infra` (configured in values).
```bash
helm upgrade --install tutup-lapak ./deploy/helm/tutup-lapak \
  --namespace gojo-infra --create-namespace \
  --set global.image.tag=$COMMIT_TAG \
  --set global.secrets.jwtSecret="$(openssl rand -hex 16)" \
  --set global.database.url="postgres://USER:PASSWORD@PG_HOST:5432/tutup_lapak?sslmode=disable"
```

## External Postgres
- Provide a hostname reachable from cluster (Cloud SQL / managed instance / on-prem via private link).
- Use a secret (db-credentials) generated by the template. Override URL with production host & credentials.
- Consider separate databases or schemas per service if needed.

## Bitnami PostgreSQL (Optional Internal DB)
Install (example):
```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm install gojo-postgres bitnami/postgresql \
  --namespace gojo-infra \
  --set auth.username=usrprd \
  --set auth.password=pswdprd \
  --set auth.database=db-tutup-lapak-prd \
  --set primary.persistence.size=1Gi \
  --set resources.requests.memory=256Mi \
  --set resources.requests.cpu=100m
```
Service DNS (default): `gojo-postgres-postgresql.gojo-infra.svc.cluster.local`

Get generated password (if not explicitly set):
```bash
kubectl get secret gojo-postgres-postgresql -n gojo-infra -o jsonpath='{.data.postgres-password}' | base64 -d
```

Construct DATABASE_URL:
```
postgres://usrprd:pswdprd@gojo-postgres-postgresql.gojo-infra.svc.cluster.local:5432/db-tutup-lapak-prd?sslmode=disable
```

Create external secret so chart skips generating its own:
```bash
kubectl create secret generic db-credentials -n gojo-infra \
  --from-literal=DATABASE_URL="postgres://usrprd:pswdprd@gojo-postgres-postgresql.gojo-infra.svc.cluster.local:5432/db-tutup-lapak-prd?sslmode=disable"
```
Then install/upgrade with:
```bash
--set global.database.existingSecret.name=db-credentials \
--set global.database.existingSecret.key=DATABASE_URL \
--set global.database.url="" # ignored if existingSecret.name is set
```

Verify connectivity (run in a debugging pod or local with port-forward):
```bash
kubectl run psql-client -n gojo-infra --image=bitnami/postgresql:16 --restart=Never -it --rm --env="PGPASSWORD=pswdprd" --command -- psql -h gojo-postgres-postgresql -U usrprd -d db-tutup-lapak-prd -c '\dt'
```

## Resource Overrides
Each service has `services.<name>.resources`. To override (example product):
```bash
--set services.product.resources.requests.cpu=100m \
--set services.product.resources.requests.memory=128Mi \
--set services.product.resources.limits.cpu=300m \
--set services.product.resources.limits.memory=384Mi
```
If unset, chart falls back to `resources.default`.

## (Learning Only) Hardcode Database URL (Insecure)
This chart supports a learning-only shortcut to inline the `DATABASE_URL` directly in every Deployment (bypassing any Secret) so you can iterate fast while debugging.

Enable (NOT for real environments):
```bash
helm upgrade --install tutup-lapak ./deploy/helm/tutup-lapak \
  --namespace gojo-infra \
  --set global.image.tag=$COMMIT_TAG \
  --set global.database.hardcode.enabled=true \
  --set global.database.hardcode.url="postgres://usrprd:pswdprd@gojo-postgres-postgresql.gojo-infra.svc.cluster.local:5432/db-tutup-lapak-prd?sslmode=disable"
```

Notes:
1. When `hardcode.enabled=true`, the chart will NOT create `db-credentials` even if `global.database.url` is set.
2. `global.database.existingSecret.*` is ignored for the connection string (you asked to hardcode it).
3. Remove this mode (set `hardcode.enabled=false`) before any shared, staging, or production deployment.
4. Hardcoding leaks credentials into pod specs, logs (via debug), `kubectl get deploy -o yaml`, and Helm release history.

Return to safer config:
```bash
helm upgrade tutup-lapak ./deploy/helm/tutup-lapak \
  --namespace gojo-infra \
  --set global.database.hardcode.enabled=false \
  --set global.database.existingSecret.name=db-credentials \
  --set global.database.existingSecret.key=DATABASE_URL
```

## Migration Jobs & Binary Options
Current images do NOT contain the `migrate` CLI, so the provided auth migration Job will fail unless you add it. Options:
1. Add to Dockerfile build stage:
   `go install github.com/golang-migrate/migrate/v4/cmd/migrate@latest` and COPY the binary into runtime image.
2. Use a lightweight separate image (e.g. bitnami/golang + curl) mounting a ConfigMap with SQL (needs refactor, since you have raw .sql already baked in repo).
3. Replace Job container image with a purpose-built migration image that includes both the compiled service binary (optional) and migrate tool.
4. Skip Job and run migrations externally via CI before helm upgrade.

Replicate Job template per service if each has migrations; ensure idempotency.
